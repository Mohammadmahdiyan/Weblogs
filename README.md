## ۴. افزودن، ویرایش و حذف محتوا (آموزش کامل)

<details>
<summary>هر پوشهٔ دارای <code>index.md</code> یک مقاله است (دسته‌های <code>media</code> و <code>books</code>)؛ ساختار پوشه‌ها، قالب md، لینک‌دادن (به مقاله، عنوان و دقیقهٔ ویدیو)، دستورهای انتشار/حذف، تاریخ‌ها، مقالهٔ آزمایشی و خروجی ساخته‌شده.</summary>

ساختار فعلی محتوا بازگشتی است: هر شاخهٔ مستقیم `content/<category>/` یک دستهٔ مستقل با همان پیشوند در نشانی است (`content/media/lives-nour/topic/index.md` → `/media/lives-nour/topic`). پوشه‌ای که `index.md` ندارد صفحهٔ فهرست پوشه است؛ پوشه‌ای که `index.md` دارد مقاله است. دسته‌های فعلی `media` و `books` هستند. کارت‌های تصویری خانه و عنوان، زیرعنوان، توضیح و تصویر آن‌ها در `content/home.json` تنظیم می‌شوند. راهنمای مرجع مسیرها، رجیستری JSON و استوری دسته‌ای: [CONTENT_PIPELINE.md](CONTENT_PIPELINE.md).

یک مقاله در هر عمقی با `index.md` شناخته می‌شود. نام پوشه فقط از `a-z`، `0-9`، `-` و `_` ساخته شود؛ هر segment در مسیر باید همین قاعده را داشته باشد.

```
my-post/
├── index.md        ← متن (هر نام .md هم قبول است؛ اگر فقط یک فایل md باشد)
├── cover.jpg       ← (اختیاری) کاور؛ عکس / گیف / ویدیو / صدا. نامش همیشه cover.*
└── diagram.png     ← هر فایل دیگر
```

### فایل md دقیقاً این‌طور نوشته می‌شود

<details>
<summary>عنوان وبلاگ اولین خط <code># </code> است؛ frontmatter فقط <code>tags</code> و <code>suggestions</code> را لازم دارد و بقیهٔ کلیدها (<code>description</code>، <code>cover</code>، <code>show</code>، <code>aliases</code> …) اختیاری‌اند.</summary>

```md
---
tags: [دفاع از اسلام, شبهه اسلام‌ستیزان]
suggestions:
  - آیا پیامبر ص با دختر 6 ساله ازدواج کرد
  - ازدواج پیامبر ص با دختر 6 ساله
---

# ازدواج پیامبر ص با مادر عایشه رض

متن وبلاگ…
```

- **نام (عنوان) وبلاگ** = اولین خطی که با `# ` شروع می‌شود. همین خط عنوان صفحه است و از متن حذف می‌شود (عنوان دوبار نمایش داده نمی‌شود).
- `tags` اختیاری است؛ اگر ننویسید هیچ برچسبی ثبت نمی‌شود.
- `suggestions` اختیاری است؛ اگر ننویسید فقط خود عنوان پیشنهاد جست‌وجو می‌شود.
- چیز دیگری لازم نیست. `date` و `updated` را دستورهای زیر خودکار می‌گذارند؛ ظاهر مقاله را خودِ خواننده از دکمهٔ «ظاهر» تغییر می‌دهد (نه از md)؛ `draft` وجود ندارد (برای وبلاگ آزمایشی از «تست» استفاده کنید). کلیدهای قدیمی (`title`، `name`، `date`، `style`، `draft`) خوانده نمی‌شوند و فقط یک هشدار می‌گیرید.
- کلیدهای اختیاری پیشرفته: `description` (خلاصهٔ سئو؛ پیش‌فرض ۱۶۰ نویسهٔ اول متن)، `readingTime` (دقیقه؛ پیش‌فرض خودکار از تعداد کلمه‌ها)، `coverEmbed` (کاور از یوتیوب/آپارات/اینستاگرام اگر `cover.*` ندارید)، `cover` (مسیر کاور با نامی غیر از `cover.*`)، `lang`، `dir`، `show` و `aliases` (فهرست نشانی‌های قدیمی برای انتقال به مسیر اصلی مقاله).

</details>

### پیوند داخلی و نام جایگزین

<details>
<summary>لینک‌های داخلی بدون <code>/Weblogs/</code> و با <code>/media/</code> یا <code>/books/</code> شروع می‌شوند؛ aliasهای مسیر قدیمی، بررسی لینک‌ها با <code>checkLinks</code> و اصلاح خودکار با <code>fixLinks</code>.</summary>

در لینک‌های داخلی **هرگز `/Weblogs/` ننویسید**؛ مسیریاب سایت پیشوند را خودش اضافه می‌کند. مسیر را از `/media/` یا `/books/` شروع کنید:

```md
[بخش همین صفحه](#دلیل-پاسخ)
[صفحهٔ دیگر همین کتاب](/books/answer-to-shobhat/alhad-noven-part1/27)
[مقالهٔ دیگر](/media/lives-nour/spider-house/example#دلیل-پاسخ)
[دقیقهٔ ۲:۳۰ ویدیو](#t=2:30)
```

مسیر قدیمی `/Weblogs/media/...` یا `/Weblogs/books/...` هم برای سازگاری پذیرفته می‌شود، اما مسیر استاندارد بدون آن است. در `index.md` می‌توانید نام‌های کوتاه و یکتای مسیر قدیمی را تعریف کنید تا به مقاله هدایت شوند:

```yaml
aliases: [elhad]
```

هر alias باید kebab-case انگلیسی و در دسته یکتا باشد. برای بررسی لینک‌های داخلی همهٔ محتوا `npm run checkLinks` را اجرا کنید. گزارش دو دسته دارد:

- **خطا (لینک شکسته):** پوشه یا کتاب ناموجود، alias ناشناخته، تیتر (`#بخش`) که در صفحهٔ موجود نیست، یا شمارهٔ صفحه‌ای بیشتر از `pageCount` کتاب. این‌ها دستور `--strict` را ناموفق می‌کنند.
- **صفحه‌های هنوز ننوشته (خطا نیست):** لینک به `pages/N.md`ای که هنوز اضافه نشده ولی شماره‌اش در محدودهٔ کتاب است (۱ تا `pageCount`، یا تا ۱۰۰۰۰ برای کتابی که `pageCount` ندارد). فقط شمرده می‌شود و برای هر کتاب خلاصه (تعداد و چند شمارهٔ اول) چاپ می‌شود؛ فهرست کامل با `npm run checkLinks -- --verbose`.

`npm run checkLinks -- --strict` فقط با خطای دستهٔ اول ناموفق می‌شود. در زمان `npm run dev` نیز خلاصهٔ بررسی نمایش داده می‌شود. برای اصلاح خودکار لینک‌های قابل‌شناسایی در یک پوشه:

```bash
npm run fixLinks -- content/books/answer-to-shobhat/alhad-noven-part1 --dry-run
npm run fixLinks -- content/books/answer-to-shobhat/alhad-noven-part1
```

#### لینک به یک عنوان (`##`، `###`، `####` و …)

<details>
<summary>لینک <code>صفحه#شناسه</code> از هر جا تا همان عنوان اسکرول و آن را هایلایت می‌کند؛ آیکن زنجیر کنار عنوان آدرسش را کپی می‌کند. شناسه چطور ساخته می‌شود و راه‌های بدون حدس‌زدن آن.</summary>

هر عنوان داخل مقاله یک شناسه (id) دارد. لینک `صفحه#شناسه` خواننده را **همان صفحه** می‌آورد، تا همان عنوان اسکرول می‌کند، عنوان را چند ثانیه هایلایت می‌کند و اگر عنوان داخل آکاردئون بسته باشد آن را باز می‌کند.

ساده‌ترین راه گرفتن لینک: ماوس را روی عنوان ببرید (در گوشی آیکن همیشه کم‌رنگ دیده می‌شود) و روی آیکن زنجیر کنار عنوان بزنید. آدرس کامل آن عنوان کپی می‌شود (مثلاً `https://…/media/lives-nour/spider-house/example#شیعه-به-علی-می‌گه-مگس`). در یک مقالهٔ دیگر فقط از `/media/…` به بعد را بنویسید:

```md
[همان بخش](/media/lives-nour/spider-house/example#شیعه-به-علی-می‌گه-مگس)
```

- **شناسه چطور ساخته می‌شود:** متن عنوان، حروف کوچک، فاصله‌ها ← `-`، نشانه‌گذاری حذف. `(ص)` و `(رض)` و ایموجی در شناسه نمی‌آیند. دو عنوان هم‌نام، شناسهٔ دومی `-1` می‌گیرد، سومی `-2` و همین‌طور.
- **اگر نمی‌خواهید شناسه را حدس بزنید:** بخشی از خود متن عنوان را در `<>` بنویسید (فاصله داخل `<>` مجاز است). اگر فقط یک عنوان آن را داشته باشد پیدا می‌شود: `[متن](</media/…/example#دلیل پاسخ>)`.
- **فاصله بدون `<>` لینک را می‌شکند:** `[متن](#دلیل پاسخ)` در Markdown لینک نیست؛ یا خط‌تیره بگذارید یا `<>`.
- `npm run checkLinks` وجود عنوان را هم بررسی می‌کند.

</details>

#### لینک به یک دقیقه از ویدیو

<details>
<summary>لینک <code>#t=2m30s</code> (یا <code>#t=2:30&amp;v=2</code>) خواننده را به همان صفحه و همان ویدیو می‌برد و از همان لحظه پخش می‌کند؛ برای فایل ویدیویی و یوتیوب. فرمت زمان، شمارهٔ ویدیو و محدودیت‌ها.</summary>

لینکی که با `#t=` شروع شود، خواننده را به همان صفحه می‌برد، تا ویدیو اسکرول می‌کند (وسط صفحه)، و ویدیو را **از همان لحظه پخش** می‌کند:

```md
[ببینید که در دقیقهٔ ۲:۳۰ چه می‌گوید](#t=2m30s)
[همین، ولی ویدیوی دوم صفحه](#t=2:30&v=2)
[ویدیو در مقالهٔ دیگر](/media/lives-nour/spider-house/example#t=1:02:03)
```

- `t` زمان است: `90` (ثانیه)، `1m30s`، `1h2m3s`، `2:30` یا `1:02:03`.
- `v` شمارهٔ ویدیو در همان مقاله است (از ۱، به ترتیب دیده‌شدن در متن). ننویسید یعنی ویدیوی اول. هم فایل ویدیویی (`![](./a.mp4)`، `::video`) و هم یوتیوب (`::youtube`) و آپارات شمرده می‌شوند. کاور بالای مقاله شمرده نمی‌شود.
- **فایل ویدیویی** (mp4 و …): از همان ثانیه پخش می‌شود.
- **یوتیوب:** قاب دوباره از همان ثانیه باز می‌شود و خودکار پخش می‌شود (هرچند ویدیو هنوز روی دکمهٔ پخش بوده باشد).
- **آپارات و سایت‌های دیگر:** صفحه تا خود ویدیو اسکرول می‌کند، ولی زمان را نمی‌شود تنظیم کرد.
- **پخش خودکار:** مرورگرها گاهی پخش بی‌صدا یا بدون لمس را می‌بندند. در آن حالت ویدیو روی همان لحظه آماده می‌ماند و فقط یک بار دکمهٔ پخش لازم است.
- در `::youtube{url="…" start="1m30s"}` زمان شروع ثابت ویدیو را تعیین می‌کند؛ لینک `#t=` همان را موقتاً جابه‌جا می‌کند.

کد: `src/lib/videoLink.ts`، `src/lib/videoSeek.ts`، `src/components/mdx/SafeEmbed.tsx` و اثر مربوطه در `src/pages/ArticlePage.tsx`.


</details>

### دستورها و انتشار خودکار

<details>
<summary>جدول دستورهای <code>publishMedia</code>، <code>deleteMedia</code> و نمونهٔ آزمایشی؛ پس از انتشار، هر ذخیره تاریخ را به‌روز و به GitHub push می‌کند (نیازمند شاخهٔ main و remote درست).</summary>

| دستور | کار |
|---|---|
| `npm run publishMedia -- <نام-پوشه>` | اعلام پایان نگارش مقاله، ثبت وضعیت تکمیل، ساخت مجدد محتوا و `git commit`/`git push` به شاخهٔ `main`؛ نام قدیمی `publishBlog` هم کار می‌کند |
| `npm run deleteMedia -- <نام-پوشه>` | حذف کامل پوشه و تاریخ‌های آن، بازسازی محتوا و push به GitHub؛ نام قدیمی `deleteBlog` هم کار می‌کند |
| `npm run createTestMedia` | ساخت مجدد مقالهٔ آزمایشی کامل در `content/media/_example-media/index.md`؛ بدون ورودی و بدون بازنویسی نمونه‌ای که از قبل وجود دارد؛ نام قدیمی `createTest` هم کار می‌کند |
| `npm run deleteTestMedia` | حذف مقالهٔ آزمایشی ثابت `_example-media`؛ بدون ورودی؛ نام قدیمی `deleteTest` هم کار می‌کند |

دیگر نیازی به دستورهای جداگانهٔ `createNewBlog` و `updateBlog` نیست. برای افزودن رسانه/مقاله، پوشهٔ آن را در `content/media/<مسیر>/` بساز و `index.md` را قرار بده؛ برای کتاب از `content/books/<مسیر>/` استفاده کن. هر دو دسته به‌صورت بازگشتی کشف می‌شوند و `story/` رزرو است. هنگام اجرای `npm run dev`، مسیرهای تازه به‌صورت خودکار در `content/<category>.json` ثبت می‌شوند و سایت بازسازی می‌شود.

**پس از اجرای `npm run publishMedia -- <نام-پوشه>`، مقاله تکمیل‌شده محسوب می‌شود.** تا وقتی `npm run dev` باز است، هر ذخیرهٔ بعدی در فایل‌ها یا رسانه‌های همان مقاله، تاریخ `updated` را خودکار به‌روز می‌کند، محتوا را بازسازی می‌کند و تغییرات مقاله را به GitHub push می‌کند. مقاله‌هایی که هنوز منتشر/تکمیل نشده‌اند خودکار push نمی‌شوند.

نمونه:

```bash
# پوشهٔ content/media/my-post از قبل ساخته شده و index.md دارد
npm run publishMedia -- my-post

# حذف کامل مقاله و انتشار حذف در سایت
npm run deleteMedia -- my-post

# ساخت/حذف نمونهٔ آزمایشی؛ هیچ نامی وارد نکنید
npm run createTestMedia
npm run deleteTestMedia
```

برای push خودکار باید مخزن محلی روی شاخهٔ `main` باشد، remote با نام `origin` به `https://github.com/mohammadmahdiyan/weblogs` متصل باشد و احراز هویت GitHub از قبل کار کند. فایل `.github/workflows/deploy.yml` سایت را پس از push به `main` می‌سازد و منتشر می‌کند؛ ممکن است نمایش تغییرات آنلاین چند دقیقه زمان ببرد.

</details>

### تاریخ‌ها (`date` و `updated`)

<details>
<summary>تاریخ‌ها و وضعیت <code>completed</code>/<code>published</code> در <code>content/media.json</code> و <code>books.json</code> نگه‌داری می‌شوند، نه در md. تا انتشار، اعلان «هنوز کامل نشده» می‌آید.</summary>

تاریخ‌ها داخل Markdown نیستند؛ برای رسانه در `content/media.json` و برای کتاب در `content/books.json` نگه داشته می‌شوند و همراه محتوای مقاله commit می‌شوند. هر مدخل شامل `date`, `updated`, `completed`, `published`, `route` و `name` است. کلید مقاله مسیر نسبی پوشه است (مثلاً `lives-nour/spider-house/topic`); هنگام ثبت خودکار، تاریخ‌ها و وضعیت قدیمی با تطبیق نام پوشهٔ پایانی حفظ می‌شود. `name` نام نمایشی است: انگلیسی از نام پوشه ساخته می‌شود و نام فارسی که نویسنده دستی گذاشته باشد حفظ می‌شود.

- پوشهٔ مقاله‌ای که در حالت توسعه شناسایی شود، به‌صورت خودکار با `completed: false` ثبت می‌شود.
- `publishBlog` مقدار `completed` را `true` می‌کند و تاریخ تکمیل/انتشار را ثبت می‌کند.
- پس از تکمیل، ذخیرهٔ هر تغییر در فایل‌ها و رسانه‌های مقاله هنگام اجرای `npm run dev` تاریخ `updated` را خودکار جلو می‌برد و به GitHub push می‌کند؛ نیازی به `updateBlog` نیست.
- **تا وقتی `publishBlog` زده نشده** (چه مقالهٔ جدید و چه قدیمی)، انتهای مقاله یک اعلان با متن «متن مقاله هنوز کامل نشده» و پیوند «پیگیری از مدیر برای تکمیل این مقاله» نمایش داده می‌شود (مقاله‌های تست `_…` هم همین‌طورند). پیوند، چت تلگرام شما را با یک پیام آمادهٔ مؤدبانه درباره‌ی همین مقاله باز می‌کند و در هر بار کلیک یکی از ۲۵ پیام می‌آید. فقط `publishBlog` نشانهٔ `"published": true` را در رجیستری دستهٔ خودش می‌گذارد و اعلان را برمی‌دارد؛ مقاله‌های قدیمی که این نشانه را ندارند اعلان می‌گیرند تا برایشان اجرا کنید. برای چند مقاله با هم: `npm run publishBlog -- مسیر-اول مسیر-دوم`. پیام‌ها در `src/lib/followUp.ts` هستند (هر تعداد قابل‌ویرایش است؛ `{title}` جای عنوان مقاله را می‌گیرد). آیدی تلگرام از اولین پیوند `t.me/…` در `social` فایل `src/site.config.ts` خوانده می‌شود؛ اگر نباشد، فقط متن اعلان نشان داده می‌شود. ظاهر اعلان در `src/index.css` (کلاس‌های `wip-*`) است.
- پوشه‌های شروع‌شونده با `_` آزمایشی هستند و در انتشار تولیدی، sitemap و RSS قرار نمی‌گیرند.

</details>

## ۵. مرجع md

<details>
<summary>جدول کلیدهای frontmatter (<code>tags</code>، <code>suggestions</code>، <code>description</code>، <code>readingTime</code>، <code>show</code>، <code>coverEmbed</code>، <code>cover</code>، <code>lang</code>/<code>dir</code>) با نوع و پیش‌فرض، و توضیح <code>show: false</code>.</summary>

| کلید | نوع | پیش‌فرض | توضیح |
|---|---|---|---|
| `# عنوان` (اولین) | متن | **الزامی** | نام/عنوان وبلاگ و `<h1>` صفحه |
| `tags` | string[] | `[]` | برچسب‌ها |
| `suggestions` | string[] | `[عنوان]` | عبارت‌هایی که جست‌وجوی دقیقشان به این وبلاگ می‌رسد |
| `description` | string | ۱۶۰ نویسهٔ اول | توضیح سئو و کارت‌ها (اختیاری) |
| `readingTime` | عدد | خودکار | دقیقهٔ مطالعه (اختیاری) |
| `show` | `true` / `false` | `true` | `false` یعنی در سایت آنلاین نمایش داده نشود (آدرسش صفحهٔ قفل نشان می‌دهد) |
| `coverEmbed` | URL https | — | کاور از یوتیوب/اینستاگرام/آپارات؛ اگر فایل کاور هست، فایل برنده است |
| `cover` | مسیر یا URL https | `cover.*` | فقط اگر کاور نامی غیر از `cover.*` دارد؛ با URL عکس (`cover: "https://…"`) چیزی برای commit کردن لازم نیست |
| `lang`, `dir` | string | — | زبان/جهت این وبلاگ (مثلاً `en` / `ltr`) |

**توضیح `show: false`:** مقاله را از سایت آنلاین (خروجی `npm run build`، مثل GitHub Pages) پنهان می‌کند: نه در خانه و جست‌وجو و sitemap و RSS هست و نه متن و فایل‌هایش در خروجی می‌آید. اگر کسی آدرس مقاله را مستقیم باز کند، صفحه‌ای ساده می‌بیند که می‌گوید «مدیر اجازهٔ نمایش این صفحه را نمی‌دهد» با دکمهٔ «درخواست از مدیر برای باز کردن قفل این صفحه» (پیام آماده در تلگرام مدیر). پیش‌فرض `show: true` است و در `npm run dev` مقاله با هر مقدار `show` دیده می‌شود تا بتوانی ویرایشش کنی.

</details>

## ۶. کاور (رسانهٔ اول)

<details>
<summary>کاور عکس فقط روی کارت فهرست دیده می‌شود؛ کاور ویدیو، صدا و embed بالای مقاله هم نشان داده می‌شوند. فایل <code>cover.*</code> خودکار شناخته می‌شود.</summary>

کاور **عکس** فقط روی کارت مقاله در فهرست (و پیش‌نمایش لینک) دیده می‌شود و بالای خود مقاله نمی‌آید؛ اگر عکسی می‌خواهید، داخل متن بگذارید. کاورِ ویدیو (با پوستر هم‌نام)، صدا (پخش‌کنندهٔ سفارشی) یا embed (با دکمهٔ پخش) چون محتواست بالای مقاله هم نشان داده می‌شود. فایلی به نام `cover.*` خودکار شناخته می‌شود.

</details>

## ۷. پیشنهادهای جست‌وجو (suggestions)

<details>
<summary><code>suggestions</code> عبارت‌هایی‌اند که جست‌وجوی دقیقشان مستقیم به مقاله می‌رود؛ جست‌وجو در متن با <code>محتوا::عبارت</code>، نتیجه‌ها با هایلایت و اسکرول به همان جا، و پیشنهاد جست‌وجوی محتوا.</summary>

```md
---
suggestions:
  - آیا پیامبر ص با دختر 6 ساله ازدواج کرد
  - دلیل ازدواج پیامبر ص با مادر عایشه رض
---

# ازدواج پیامبر ص با مادر عایشه رض
```

اگر `suggestions` ننویسید، فقط عنوان پیشنهاد جست‌وجو است.

اگر کاربر دقیقاً یکی از این عبارت‌ها (یا عنوان) را جست‌وجو و Enter بزند، مستقیم به مقاله می‌رود. مقایسه پس از نرمال‌سازی است: یکسان‌سازی «ي/ی» و «ك/ک»، حذف اعراب و نیم‌فاصله، تبدیل ارقام فارسی/عربی به لاتین، حروف کوچک و فاصله‌های اضافه. تطبیق تقریبی فقط لیست نتایج را نشان می‌دهد.

**جست‌وجو در محتوا:** با نوشتن `محتوا::عبارت` در کادر جست‌وجوی صفحهٔ خانه، داخل متن مقاله‌ها جست‌وجو می‌شود. اگر عبارتی در عنوان/پیشنهادها پیدا نشود، دو مورد نشان داده می‌شود: «می‌خواهید در محتوا جست‌وجو کنید؟» (با کلیک، کادر به `محتوا::عبارت` تغییر می‌کند و در متن جست‌وجو می‌شود) و «نتیجه‌ای پیدا نشد». اگر جست‌وجوی محتوا هم چیزی نیافت، فقط «نتیجه‌ای پیدا نشد» می‌آید و پیشنهاد دوباره نمی‌آید.

**نتایج جست‌وجوی محتوا:** خط اول هر نتیجه نام مقاله است. زیرش توضیحی هست که عبارت پیداشده همیشه در **وسط** آن است، با تعداد نویسهٔ برابر قبل و بعدش (اگر عبارت نزدیک ابتدا یا انتهای متن باشد، از همان طرف متن کمتری هست). اگر عبارت چند بار در یک مقاله باشد، کنار نتیجه دو دکمهٔ فلش بالا (مورد قبلی) و پایین (مورد بعدی) و شمارندهٔ «۲ از ۵» هست؛ با هر کلیک، متن قبل و بعد همان مورد نمایش داده می‌شود. در اولین مورد فلش بالا و در آخرین مورد فلش پایین غیرفعال است و اگر فقط یک مورد باشد هر دو غیرفعال‌اند. با کلیک روی نتیجه (یا Enter)، مقاله باز می‌شود و **خودکار تا همان جایی که متن نوشته شده اسکرول** می‌کند و آن را (حدود ۵ ثانیه) هایلایت می‌کند؛ مورد انتخاب‌شده با `&n=شماره` در آدرس می‌آید؛ اگر داخل آکاردئون یا `<details>` بسته باشد، اول باز می‌شود. این با پارامتر `?find=عبارت` در آدرس مقاله کار می‌کند (کد: `src/lib/findInPage.ts`).

### جست‌وجوی آیه و متن اعراب‌دار

<details>
<summary>لازم نیست اعراب بنویسید: حرکات، تشدید، تنوین، علامت‌های قرآنی و کشیده در همهٔ جست‌وجوها نادیده گرفته می‌شود و شکل‌های الف/ی/ک یکی حساب می‌شوند.</summary>

لازم نیست اعراب بگذارید. در همهٔ جست‌وجوها (عنوان، `محتوا::` و هایلایت داخل مقاله) حرکات، تنوین، تشدید، علامت‌های قرآنی (رسم عثمانی) و کشیده نادیده گرفته می‌شود و شکل‌های الف (آ أ إ ٱ)، ؤ، ئ، ة و ي/ی و ك/ک یکی حساب می‌شوند. پس در صفحهٔ اصلی بنویسید `محتوا::يضرب مثلا ما` یا `محتوا::ان الله لا يستحيي` تا مقالهٔ دارای `يَضْرِبَ مَثَلًا مَا` پیدا و همان تکه هایلایت شود.

</details>

</details>

## ۱۰. افزودن کامپوننت/تگ جدید

<details>
<summary>مثال گام‌به‌گام ساخت <code>:::note</code>: کامپوننت React، ثبت در <code>directiveNames</code>، نقشهٔ کامپوننت‌ها و مستندسازی.</summary>

مثال کامل `:::note`:

1. `src/components/mdx/Note.tsx`:
   ```tsx
   import type { ReactNode } from 'react'
   export function Note({ children }: { children?: ReactNode }) {
     return <aside className="not-prose my-4 rounded-[var(--radius-md)] border border-[var(--border-strong)] bg-[var(--surface-alt)] p-4">{children}</aside>
   }
   ```
2. نام را در `directiveNames` در `src/lib/markdown.ts` اضافه کنید: `'note'`.
3. در `src/components/MarkdownRenderer.tsx` نقشهٔ کامپوننت‌ها: `'mdx-note': withMdxErrorBoundary('note', Note),` و در صورت نیاز نام را به مجموعهٔ unwrap اضافه کنید.
4. در `docs/COMPONENTS.md` مستند کنید و استفاده: `:::note` … `:::`.

فقط از توکن‌های رنگی (`var(--surface-alt)` و …) استفاده کنید تا با هر رنگ‌بندی هماهنگ شود.

</details>

## ۱۱. ظاهر مقاله (تغییرات جزئی)

<details>
<summary>چیدمان مقاله یکی است و خواننده فقط از دکمهٔ «ظاهر» رنگ‌بندی، آکاردئون، نقل‌قول و دکمه را عوض می‌کند؛ نحوهٔ کار با attributeهای روی <code>&lt;html&gt;</code> و افزودن گزینهٔ جدید. زیرموضوع‌ها: نقل‌قول‌ها، بسم‌الله، آکاردئون چت، متن کوچک و ایموجی.</summary>

چیدمان صفحهٔ مقاله **فقط یکی** است و خواننده نمی‌تواند کل صفحه را عوض کند. به‌جایش در صفحهٔ هر وبلاگ دکمهٔ «ظاهر» در هدر هست که فقط این تغییرهای جزئی را می‌دهد:

| گروه | گزینه‌ها |
|---|---|
| رنگ‌بندی | سبز (پیش‌فرض)، آبی، بنفش، قرمز، نارنجی، فیروزه‌ای، خاکستری (هرکدام برای حالت روشن و تیره) |
| آکاردئون (`:::item`) | پر (پیش‌فرض)، کادردار، ساده |
| نقل‌قول (`>`) | کارتی (پیش‌فرض)، خط کناری، کادردار |
| دکمه (`:button`، مودال) | معمولی (پیش‌فرض)، گرد، برجسته |

انتخاب خواننده در مرورگرش ذخیره می‌شود و روی همهٔ صفحه‌های سایت اثر می‌گذارد؛ دکمهٔ «بازگشت به حالت پیش‌فرض» همه را برمی‌گرداند. فایل md هیچ کلیدی برای ظاهر ندارد.


**چطور کار می‌کند:** هر انتخاب یک attribute روی `<html>` می‌گذارد (`data-palette`، `data-accordion`، `data-quote`، `data-button`) و فقط CSS همان گزینه فعال می‌شود. منطق و فهرست گزینه‌ها در `src/lib/appearance.ts`، رنگ‌بندی‌ها در انتهای `src/styles/theme.css` و بقیه در `src/styles/blog-styles.css` هستند. `index.html` انتخاب ذخیره‌شده را پیش از React اعمال می‌کند تا پرشی دیده نشود.

**افزودن گزینهٔ جدید:** یک گزینه به `appearanceGroups` در `src/lib/appearance.ts` اضافه کنید (برای رنگ‌بندی، `swatch` هم بدهید) و قاعدهٔ CSS آن را بنویسید، مثلاً `[data-button='square'] .md-button { border-radius: 0 }`. برای رنگ‌بندی جدید دو خط در `theme.css` کافی است (`:root[data-palette='x']` و `.dark[data-palette='x']`؛ فقط توکن‌های `--brand*`).

### شکل‌های نقل‌قول در md (`>`، `>>`، `>$`)

<details>
<summary>نقل‌قول ساده، چندخطی (<code>&gt;&gt;</code> … <code>&lt;&lt;</code>)، چند نقل‌قول در یک باکس و نقل‌قول بازشونده برای متن طولانی (<code>&gt;$</code>) که فقط ۴ خط اولش دیده می‌شود؛ همچنین استایل لینک داخل نقل‌قول.</summary>

**شکل‌های نقل‌قول در md:**

```md
> نقل‌قول یک‌خطی

>> نقل‌قول طولانی
که چند خط (حتی خط خالی) دارد
و با << در انتهای آخرین خط بسته می‌شود<<

> متن اول
> متن دوم

>$ یک متن خیلی طولانی که فقط چند خطش دیده می‌شود

>$ نقل‌قول بلند اول
>$ نقل‌قول بلند دوم
```

- `> …`: نقل‌قول ساده. خطی که `>` ندارد و درست زیر آن آمده ادامهٔ همان نقل‌قول است (با فاصله چسبیده می‌شود)؛ یک خط خالی نقل‌قول را تمام می‌کند.
- `>> … <<`: یک نقل‌قول که اینترها و خط‌های خالی داخلش حفظ می‌شود. اگر `<<` نیاید، مثل قبل (نقل‌قول تودرتو) خوانده می‌شود.
- چند خط پشت‌سرهم که هرکدام با `>` شروع می‌شوند: هر خط یک نقل‌قول جدا، همه در یک باکس (هرکدام آیکون‌های خودش را دارد). اگر داخلشان لیست/کد/نقل‌قول تودرتو باشد، مثل مارک‌داون معمولی می‌ماند.
- `>$ …`: **نقل‌قول بازشونده برای متن طولانی.** فقط ۴ خط اول دیده می‌شود، خط آخرِ دیده‌شده کم‌رنگ است و روی نقل‌قول (یا فلش پایینش) که کلیک شود بقیه باز می‌شود؛ با فلش بالا دوباره بسته می‌شود. `$` باید به `>` بچسبد و بعدش فاصله بیاید (`> $5` نقل‌قول معمولی است). متن را مثل `>` در **یک خط** بنویسید. نقل‌قولی که در همان ۴ خط جا شود، همان‌طور کامل دیده می‌شود و فلش ندارد.
- چند خط `>$` پشت‌سرهم: هرکدام یک نقل‌قول بازشونده جدا در یک باکس. `>$` و `>` را هم می‌شود قاطی کرد (کوتاه‌ها کامل، بلندها بازشونده).
- متنی که جست‌وجو یا لینک `?find=` به داخل یک نقل‌قول بسته اشاره کند، آن را خودکار باز می‌کند. در چاپ همه کامل چاپ می‌شوند. تعداد خط‌ها با `--quote-long-lines` در CSS قابل تغییر است (پیش‌فرض ۴).
- **لینک داخل نقل‌قول** (هر نوعش) به‌شکل برچسب رنگی با خط زیرین نرم دیده می‌شود تا از لینک‌های بیرون نقل‌قول زیباتر و متمایز باشد (`.md-quote a` در `src/styles/blog-styles.css`).

منطق در `src/lib/quotes.ts` است.

**نقل‌قول:** آیکون نقل‌قول دیگر روی متن نمی‌افتد؛ یکی اول متن و یکی آخر متن می‌آید و آیکون آخر ۱۸۰ درجه چرخیده است. اندازهٔ آیکون‌ها `size-4` است (در `QuoteIcon` در `src/components/MarkdownRenderer.tsx` تغییر می‌کند).


</details>

### آکاردئون به‌شکل چت (سوال و جواب)

<details>
<summary>داخل <code>:::item</code>، خط‌های <code>سوال۱: (…)</code> و <code>جواب۱: (…)</code> به‌شکل حباب چت نمایش داده می‌شوند؛ قواعد پرانتز و مودال داخل آکاردئون.</summary>

داخل هر `:::item`، خط‌هایی که با `سوال`/`س` یا `جواب`/`ج` شروع شوند و متنشان داخل پرانتز باشد، به‌شکل چت مدرن نمایش داده می‌شوند:

```md
:::item{title="پرسش و پاسخ"}
سوال1 : (آیا این روایت سند معتبر دارد؟)
جواب1 : (خیر. سند آن ضعیف است.)
س2 : (پس منبع دیگری هست؟)
ج2 : (جواب می‌تواند چند خط هم باشد)
این متن بیرون از پرانتز است و مثل متن عادی آکاردئون می‌آید.
:::
```

- شمارهٔ بعد از سوال/جواب اختیاری است. علامت `:` یا `：` هر دو درست است.
- فقط متن **داخل پرانتز** حباب چت می‌شود؛ هر متنی بیرون پرانتز، متن معمولی آکاردئون است.
- داخل حباب می‌شود بولد، لینک، لیست و پرانتز تودرتو (مثل `(ص)`) نوشت؛ «۱) …» هم حباب را نمی‌بندد.
- اگر پرانتزی بسته نشود، آکاردئون همان‌طور که نوشته‌اید (متن عادی) نمایش داده می‌شود.

**مودال داخل آکاردئون:** دیگر لازم نیست تعداد `:` را حساب کنید؛ تودرتو بودن خودکار درست می‌شود (`src/lib/directives.ts`)، و عنوان مودال دیگر به‌عنوان سؤال اضافه در داده‌های ساختاریافتهٔ سئو (FAQ) نمی‌رود.

</details>

### متن کوچک و ایموجی (داخل متن)

<details>
<summary><code>((متن))(سایز، قرارگیری)</code> برای متن کوچک بالا/وسط/پایین، و استیکر با خود ایموجی (یا <code>{😂}</code>) که در <code>src/emojis/emojis.ts</code> ثبت می‌شود.</summary>

**متن کوچک** (مثل ³¹²⁴ در تلگرام):

```md
((سلام دنیا))
((سلام دنیا))(سایز: کوچک،قرارگیری: وسط)
((۳))(قرارگیری: پایین)
```

- `سایز`: `کوچک`، `متوسط`، `بزرگ` — پیش‌فرض `متوسط`
- `قرارگیری`: `بالا`، `وسط`، `پایین` — پیش‌فرض `بالا`
- هرکدام را می‌شود ننوشت (`((x))(سایز: کوچک)`) و ترتیب مهم نیست. جداکننده `،` یا `,` است. بدون تنظیمات یعنی `((سلام دنیا))(سایز: متوسط،قرارگیری: بالا)`.
- متن داخل `(( ))` فقط متن ساده باشد (بدون ** و لینک). در جست‌وجو و فهرست مطالب، خود متن حساب می‌شود نه تنظیمات.

**استیکر** با خودِ ایموجی (یا داخل آکولاد، `{😂}`):

```md
این خنده‌دار بود 😂 واقعا ♥
```

نام‌ها و فایل هرکدام در **یک فایل** `src/emojis/emojis.ts` است (کنار خود فایل‌های `.svg` همان پوشه):

```ts
export const emojis = {
  '😂': 'funnyface.svg',
  '🤣': 'funnyface.svg',
  '♥': 'heart.svg',
}
```

برای افزودن: فایل svg را در `src/emojis/` بگذارید و یک خط `'😍': 'فایل.svg',` به `emojis.ts` اضافه کنید (چند ایموجی می‌توانند یک svg مشترک داشته باشند). فقط ایموجی‌های ثبت‌شده تبدیل می‌شوند؛ هر ایموجی یا `{چیز دیگری}` همان متن می‌ماند. موجودها: 😂 🤣 🙂 😉 😎 😮 😭 😡 ♥. (داخل کد تبدیل نمی‌شود.)

</details>

## ۱۸. جاسازی محتوای خارجی (iframe)

<details>
<summary>یوتیوب (با ثانیهٔ شروع)، اینستاگرام، آپارات، صفحهٔ دلخواه و کارت منبع <code>:::source</code>؛ allowlist، محدودیت‌ها، امنیت و سئو.</summary>

| می‌خواهم… | از این استفاده کنید |
|---|---|
| ویدیوی یوتیوب (حتی از ثانیهٔ مشخص) | `::youtube{url="…" start="1m30s"}` |
| پست/ریل اینستاگرام | `::instagram{url="…"}` |
| ویدیوی آپارات | `::aparat{id="…"}` |
| صفحهٔ دیگری (مثلاً سایت احادیث) به‌عنوان مدرک | `::embed{src="https://…" height="500"}` |
| نقل متن حدیث و حکم آن، قابل جست‌وجو و چاپ | `:::source{site="…" grade="daif" url="…"}` |
| کد iframe آماده | همان `<iframe>` (خودکار امن می‌شود) |

- **allowlist:** میزبان سایت احادیث خود را به `embedAllowlist` در `src/site.config.ts` اضافه کنید. میزبان‌های خارج از لیست هم نمایش داده می‌شوند ولی با برچسب «محتوای خارجی».
- **صفحهٔ متنی:** `height="500"` بدهید تا داخل کادر اسکرول شود. iframe نمی‌تواند فقط «بخشی» از صفحه را نشان دهد.
- **محدودیت:** بسیاری از سایت‌ها iframe را مسدود می‌کنند. پس از ۸ ثانیه کارت جایگزین با دکمهٔ «مشاهده در منبع» نمایش داده می‌شود.
- **امنیت:** `sandbox`، `referrerpolicy`، بارگذاری تنبل، بدون پخش خودکار، فقط https. در `public/_headers` (خودکار) CSP `frame-src` فقط برای میزبان‌های allowlist ساخته می‌شود.
- **سئو:** محتوای iframe ایندکس نمی‌شود؛ وزن سئو با متن مقاله و `:::source` است.

</details>

## ۱۹. گالری (مجموعهٔ عکس / گیف / ویدیو)

<details>
<summary><code>:::gallery</code> هر ترکیب عکس/گیف/ویدیو را می‌گیرد و چیدمان را بر اساس تعداد و اندازهٔ فونت تنظیم می‌کند؛ کلیک بزرگ‌نمایی با پیمایش بین همهٔ موردها باز می‌کند.</summary>

هر ترکیبی از عکس، گیف و ویدیو (به هر تعداد) داخل یک `:::gallery` قرار می‌گیرد؛ هر مورد را در یک خط جدا بنویسید. کلیک روی هر مورد پنجرهٔ بزرگ‌نمایی را باز می‌کند و با کلیدهای جهت‌دار می‌شود بین همهٔ موردهای همان گالری رفت.

| تعداد | چیدمان |
|---|---|
| ۱ | گالری نیست؛ همان رسانه با اندازهٔ عادی |
| ۲ | یکی راست، یکی چپ |
| ۳ | دو تا بالا (راست و چپ)، یکی پایین با تمام عرض |
| ۴ | مثل پنجره: دو تا بالا، دو تا پایین |

| ۶ | سه تا بالا، سه تا پایین |

## ۲۰. استوری روزانه (حلقهٔ هدر)

<details>
<summary>حلقهٔ کنار منوی هدر استوری امروز را باز می‌کند؛ هر فایل یک استوری است، scopeهای خانه/رسانه/کتاب، فرانت‌متر <code>show</code>/<code>blog</code>/<code>seconds</code>، دستورهای انتشار و پاک‌سازی و انتخاب خودکار.</summary>

حلقهٔ رنگی کنار منوی هدر، عکس پروفایل شما (از `src/site.config.ts` ← `profile.avatar`) است. با کلیک، استوری امروز باز می‌شود: نوار پیشرفت (هر استوری یک بخش)، لمس سمت چپ/راست کارت برای بعدی/قبلی (در راست‌به‌چپ: چپ = بعدی)، نگه‌داشتن برای توقف، دکمه‌های کنار کارت در دسکتاپ، و کلیدهای Esc و جهت‌ها. بعد از دیدن، حلقه خاکستری می‌شود.

**عکس پروفایل:** فایل را در `public/` بگذارید (مثلاً `public/profile.jpg`) و بنویسید `profile: { name: '…', avatar: 'profile.jpg' }`. همین عکس در جواب‌های چت آکاردئون هم دیده می‌شود.

**هر فایل = یک استوری.** هر پوشهٔ scope مستقل است و تعداد استوری‌ها برابر تعداد فایل‌هاست؛ ترتیب نام فایل طبیعی است (۲ قبل از ۱۰):

```
story/                                  ← scope خانه (/)
content/media/story/                    ← scope رسانه‌ها (/media/**)
content/books/story/                    ← scope کتاب‌ها (/books/**)
```

- هر فایل یک md معمولی است: متن، **پررنگ**، نقل‌قول، `||متن سانسورشده||`، لینک، عکس و ویدیو (`![](./photo.jpg)` که عکس را هم داخل `story/` می‌گذارید). متن بلند خودش اسکرول نرم دارد و تا وقتی می‌خوانید یا اسکرول می‌کنید، زمان استوری منتظر می‌ماند.
- فایل عکسی که هیچ md استفاده‌اش نکرده، خودش یک استوری تمام‌صفحه است. md که فقط یک عکس باشد هم همین‌طور.
- برای scope رسانه/کتاب، عکس‌ها را کنار فایل‌های همان پوشهٔ `story/` بگذارید؛ این فایل‌ها برخلاف رسانه‌های مقاله، از Git نادیده گرفته نمی‌شوند.
- فرانت‌متر اختیاری بالای هر فایل:
  - `show: false` ← اگر همهٔ اسلایدهای آن پوشه پنهان باشند، حلقهٔ همان scope آن روز نشان داده نمی‌شود و استوری خودکار جایگزینش نمی‌شود.
  - `blog: عنوان مقاله/عنوان بخش` ← به‌جای متن فایل، همان بخش از مقاله نشان داده می‌شود، با دکمهٔ «خواندن مقاله». مثال: `blog: غدیر ، عید سیاسی/شاید بگویند`. اگر کل متن فایل فقط همین یک خط باشد هم کار می‌کند. به‌جای عنوان می‌توانید نام پوشهٔ مقاله را بنویسید. اگر مقاله یا بخش پیدا نشود، `publishStory` با فهرست بخش‌های موجود خطا می‌دهد. مقالهٔ +۱۸ در استوری نمی‌آید.
  - `seconds: 12` ← مدت نمایش همین استوری (پیش‌فرض: خودکار، بر اساس طول متن).

**انتشار و پاک‌سازی:** state هر سه scope در `content/story-state.json` نگهداری می‌شود:

```sh
npm run publishStory                 # انتشار scope خانه
npm run publishStory -- media        # انتشار scope رسانه‌ها
npm run publishStory -- books        # انتشار scope کتاب‌ها
npm run cleanStory                   # پاک‌کردن همهٔ scopeهای منقضی
npm run deleteStory -- home          # حذف فوری scope خانه
npm run deleteStory -- media         # حذف فوری scope رسانه‌ها
npm run deleteStory -- books         # حذف فوری scope کتاب‌ها
```

هر فرمان انتشار، فقط پوشهٔ همان scope و فایل state مشترک را commit و push می‌کند. GitHub Actions هر روز (۰۰:۰۵ تهران) همهٔ scopeهای منقضی را پاک می‌کند؛ حتی اگر اجرا دیر شود، بیلد استوری روز قبل را نشان نمی‌دهد. در `npm run dev` پوشهٔ منتشرنشده هم به‌صورت پیش‌نمایش دیده می‌شود.

در هدر، ابتدا استوری دستی امروزِ scope جاری نمایش داده می‌شود؛ اگر نباشد، استوری خودکار نزدیک‌ترین پوشهٔ والد، سپس استوری خودکار کل همان scope و در پایان استوری خانه انتخاب می‌شود. مسیر `/` همیشه scope خانه است. انتخاب خودکار برای هر روز و scope ثابت است و فقط از مقاله‌های غیرآزمایشی، غیر +۱۸، قابل‌نمایش و (در production) کامل‌شده استفاده می‌کند؛ بخش واجد شرایط باید تیتر سطح `##`، دست‌کم ۱۴۰ نویسه متن ساده و حداکثر ۴۰۰۰ نویسه Markdown داشته باشد. زمان پایهٔ هر استوری: `story.slideSeconds` در `site.config.ts`؛ خاموش کردن: `story.enabled: false`.


</details>

## ۲۱. صفحهٔ کتاب‌ها (`/books`)

<details>
<summary>کتاب‌ها مثل مقاله‌ها ساخته می‌شوند ولی مجموعهٔ جدایی‌اند؛ نوشتن صفحه‌به‌صفحه با <code>pages/N.md</code>، <code>pageCount</code>، دکمه‌های پیمایش، جست‌وجوی کتاب و پرش مستقیم به صفحه.</summary>

کتاب‌ها یک مجموعهٔ جدا هستند که دقیقاً همان قالب و همان ساخت مقاله‌ها را دارند، پس همهٔ قابلیت‌های md (آکاردئون، چت، نقل‌قول، گالری، کاور، suggestions …) در آن‌ها کار می‌کند.

- هر کتاب یک پوشه در `content/books/<مسیر-پوشه>/index.md` است. نام کامل مسیر در نشانی حفظ می‌شود: `/books/<مسیر-پوشه>`.
- صفحهٔ `/books` مثل صفحهٔ خانه فهرست صفحه‌بندی‌شده، جست‌وجوی عنوان و جست‌وجوی داخل متن (`محتوا::عبارت`) دارد. لینک «کتاب‌ها» در `nav` و `footerLinks` فایل `src/site.config.ts` است.
- دستورها (مثل وبلاگ):
  - `npm run publishBook -- نام-پوشه` ← انتشار و push (بدون آن، صفحه با یادداشت «هنوز تمام نشده» دیده می‌شود)
  - `npm run deleteBook -- نام-پوشه` ← حذف
  - `npm run createTestBook` / `npm run deleteTestBook` ← کتاب آزمایشی `content/books/_example-book` (فقط در `npm run dev` دیده می‌شود، مثل `_example-article`)
- **صفحه‌صفحه نوشتن:** کتاب بلند را با پوشهٔ `pages/` کنار `index.md` بنویسید و **نام هر فایل، شمارهٔ صفحه** باشد: `pages/1.md`، `pages/2.md` … `index.md` فقط مشخصات و معرفی کتاب است (عنوان، برچسب، کاور، suggestions). برای نمونه، `content/books/answer-to-shobhat/alhad-noven-part1/pages/27.md` در نشانی `/books/answer-to-shobhat/alhad-noven-part1/27` باز می‌شود. بالای هر فایل صفحه می‌توانید `title: "فصل اول"` بنویسید. شماره‌ها لازم نیست پشت سر هم باشند و برای اضافه کردن صفحهٔ ۳۷ فقط `37.md` را بسازید (هیچ فایلی تغییر نام نمی‌دهد). عکس صفحه‌ها را کنار خود فایل (`pages/`) یا در پوشهٔ کتاب بگذارید.
- اگر تعداد کل صفحه‌ها معلوم است، در frontmatter معرفی کتاب `pageCount: 563` را بنویسید. لینک به صفحهٔ موجود باز می‌شود؛ صفحه‌ای که هنوز فایلش اضافه نشده ولی شماره‌اش در محدودهٔ `pageCount` است، صفحهٔ دوستانهٔ «هنوز اضافه نشده» با لینک معرفی و نزدیک‌ترین صفحه‌های موجود را نشان می‌دهد. کتابی که `pageCount` ندارد، وقتی پوشهٔ `pages/` دارد شماره‌های ۱ تا ۱۰۰۰۰ را صفحهٔ در انتظار در نظر می‌گیرد.
- **دکمه‌های زیر کتاب:** صفحهٔ قبل/بعد، ده، صد، هزار و ده‌هزار صفحه قبل/بعد (هر کدام فقط وقتی آن‌قدر صفحه در آن سمت هست) دکمه‌های «اولین» و «آخرین» (صفحهٔ شمارهٔ اول و آخر) و کادر «برو به» که شمارهٔ آخرین صفحه در آن به‌عنوان نمونه دیده می‌شود (کتاب ۱۰۰ صفحه‌ای: ۱۰۰، ۴۰۰۰ صفحه‌ای: ۴۰۰۰). کتابی که `pages/` ندارد (فقط `index.md`) هیچ دکمه‌ای ندارد. جست‌وجوی `محتوا::` داخل همهٔ صفحه‌ها هم می‌گردد و مستقیم به همان صفحه می‌برد.
- **جست‌وجوی صفحهٔ کتاب‌ها:** با تایپ بخشی از نام، کتاب‌هایی که آن را دارند فهرست می‌شوند (`شرح صح` ← «شرح صحیح مسلم» و «شرح صحیح بخاری»). دکمهٔ فلش رو به بالا کنار هر مورد، نام کامل را در کادر می‌گذارد؛ ↑ و ↓ بین موارد جابه‌جا می‌شوند، `Tab` مورد انتخاب‌شده (یا اولی) را کامل می‌کند و `Enter` کتاب را باز می‌کند. برای رفتن مستقیم به یک صفحه بنویسید `شرح صحیح بخاری ص۲۱۶` یا `… صفحه۲۱۶` یا `… صفحه ۲۱۶` و Enter بزنید. اگر آن صفحه در کتاب نباشد، آخرین صفحهٔ کتاب را می‌گوید.
- تاریخ‌ها، route و نام نمایشی در `content/books.json` نگه‌داری می‌شوند و `npm run dev` کتاب‌های تو‌در‌تو را خودکار ثبت می‌کند. رسانهٔ کتاب‌ها در مسیر عمومی جداگانه منتشر می‌شود و مسیر کتاب را حفظ می‌کند.
- مقاله‌ها و کتاب‌ها جدا هستند: جست‌وجو، فهرست و استوری دسته‌ای هرگز محتوای دو دسته را با هم مخلوط نمی‌کنند؛ sitemap و RSS نیز مسیرهای فعلی `/media` و `/books` را ثبت می‌کنند.

</details>

## ۲۲. منبع (sources) در انتهای مقاله

<details>
<summary>با <code>source</code>/<code>sources</code> در frontmatter، انتهای مقاله آکاردئون «منابع» با نوع هر مورد (یوتیوب، تلگرام، ویکی‌پدیا، عکس، PDF …) نشان داده می‌شود.</summary>

در frontmatter مقاله (یا معرفی کتاب) بنویسید:

```yaml
---
sources:
  - https://www.youtube.com/watch?v=abc          # ویدیو یوتیوب
  - https://t.me/channel/123                     # پست تلگرام
  - https://example.com/page                     # وب‌سایت
  - https://example.com/document.jpg             # عکس (پیش‌نمایش هم دارد)
  - ویدیو آموزش | https://example.com/video      # «عنوان | آدرس»
  - کتاب فلان، جلد ۲، صفحهٔ ۴۰                    # متن ساده، بدون لینک
---
```

اگر منبع فقط یکی است: `source: https://youtu.be/abc` (کلیدهای `source`، `sources`، `منبع` و `منابع` هر چهار کار می‌کنند). انتهای مقاله یک آکاردئون بسته «منبع» (یا «منابع (۳)») نشان داده می‌شود و هر مورد نوعش را دارد: ویدیو یوتیوب، کانال یوتیوب، ویدیو آپارات، پست تلگرام، اینستاگرام، توییتر (X)، ویکی‌پدیا، گیت‌هاب، آرشیو اینترنت، عکس، ویدیو، صوت، فایل PDF یا وب‌سایت. لینک‌ها در تب جدید باز می‌شوند. فقط آدرس‌های `https://`، `http://` و `tg://` لینک می‌شوند. متنی که `: ` (دونقطه و فاصله) دارد را داخل گیومه بنویسید، چون در YAML معنی دیگری دارد. منبع صفحه‌های کتاب (`pages/N.md`) فعلاً فقط برای معرفی کتاب (`index.md`) است.

</details>

## ۲۳. خط جداکننده

<details>
<summary><code>---</code> یک خط نازک و <code>--- متن ---</code> همان خط با متن وسطش؛ قبل از آن خط خالی بگذارید.</summary>

- یک خط فقط شامل `---` (با یک خط خالی قبل و بعدش) ← یک خط نازک و کم‌رنگ به عرض کامل متن، با کمی فاصله از چپ و راست.
- `--- سلام دنیا ---` ← همان خط، با متن «سلام دنیا» در وسطش (در کپی تلگرام: یک ردیف خط‌تیره با متن وسط). متن می‌تواند `**پررنگ**` یا لینک هم داشته باشد و باید در یک خط باشد.
- حتماً قبل از `---` یک خط خالی بگذارید، وگرنه Markdown خط بالایی را «تیتر» می‌کند.

</details>

## ۲۴. کپی متن برای تلگرام

<details>
<summary>دکمهٔ «کپی متن مقاله» و کلیک روی عنوان یا نقل‌قول، متن را با قالب تلگرام (بولد، اسپویلر، لینک، افتخاری‌ها …) کپی می‌کند.</summary>

- انتهای هر مقاله (بالای کادر «پیگیری از مدیر») یک دکمهٔ **«کپی متن مقاله»** هست که کل مقاله را برای تلگرام کپی می‌کند.
- روی هر **عنوان** (`##`، `###` و …) کلیک کنی، همان عنوان با کل بخشش (تا عنوان بعدیِ هم‌سطح یا بالاتر) کپی می‌شود؛ روی یک **نقل‌قول** کلیک کنی همان نقل‌قول کپی می‌شود. کلیک روی لینک و دکمه‌ها و انتخاب متن با موس اثری ندارد.
- نتیجه با `react-toastify` نشان داده می‌شود و در صورت خطا، جزئیاتش در کنسول مرورگر (`console.error`) می‌آید. بعد از دریافت پروژه یک بار `npm install` بزن.
- قالب‌ها: بولد، ایتالیک، زیرخط، خط‌خورده، mono، اسپویلر (`||متن||`)، نقل‌قول (`<blockquote>`) و لینک. هم HTML و هم متن ساده (با `**بولد**`، `__ایتالیک__`، `||اسپویلر||`) کپی می‌شود.
- **افتخاری‌ها** به عبارت کامل نوشته می‌شوند: `(ص)` ← `(ﷺ)`، `(ع)` ← `(علیه السلام)`، `(جل)` ← `(جل جلاله)` و بقیهٔ جدول `src/lib/honorifics.ts`.
- **عکس، ویدیو و صدا** فقط با نام فایلشان (با پسوند) کپی می‌شوند، مثل `17hazar-in-qadir-top-site.png`. اگر چند تا از یک نوع باشد از بالا شماره می‌خورند: `1. a.jpg`، `2. b.jpg`.
- اینترهای متن حفظ می‌شود.

کد: `src/lib/telegram.ts` (تبدیل)، `src/lib/clipboard.ts` (کپی)، `src/components/TelegramCopy.tsx` (دکمه و کلیک روی عنوان‌ها).

</details>

## ۲۵. پایان‌دادن به یک بخش (عنوان تکراری)

<details>
<summary>برای تمام‌کردن کپی یک <code>###</code> پیش از جای معمولش، همان عنوان را با دقیقاً همان متن دوباره بنویسید؛ عنوان دوم نه کپی می‌شود و نه نمایش داده می‌شود.</summary>

کپی یک `###` (یا `####` و …) تا عنوان بعدیِ هم‌سطح یا بالاتر ادامه دارد. اگر متنِ بعد از یک جا ادامهٔ بخش بالاتر است، همان عنوان `###` را با **دقیقاً همان متن** دوباره بنویس؛ کپی همان‌جا تمام می‌شود و عنوان دوم نه کپی می‌شود، نه در صفحه و فهرست مطالب دیده می‌شود:

```md
### این یک متن تست است

متن داخلش

### این یک متن تست است

این متن دیگر جزو بخش بالا نیست و کپی نمی‌شود.
```

شرط: عنوان تکراری باید هم‌سطح و هم‌متن باشد و نزدیک‌ترین عنوانِ هم‌سطح یا بالاتر پیش از آن، همان عنوان اول باشد (عنوان‌های ریزتر بینشان مانعی ندارند). عنوان هم‌نامی که زیر دو بخش `##` متفاوت آمده، علامت پایان حساب نمی‌شود. برای `##` این قاعده فعال نیست. کد: `src/lib/closingHeadings.ts`.


</details>

## ۲۶. کپی متن انتخاب‌شده (لینک به همان جای متن)

<details>
<summary>با انتخاب متن، کادری زیرش باز می‌شود: کپی متن عادی، کپی برای تلگرام به‌صورت لینک، کپی کد مارک‌داون؛ لینک تا همان جای متن اسکرول و آن را هایلایت می‌کند.</summary>

هر متنی که داخل مقاله با موس یا لمس انتخاب شود، یک کادر کوچک زیرش باز می‌کند:

1. **کپی متن عادی**: فقط خود متن.
2. **کپی برای تلگرام (لینک)**: متن به‌صورت لینک آبی کپی می‌شود که با کلیک، همین صفحه را باز می‌کند و دقیقاً تا همان جای متن اسکرول و آن را هایلایت می‌کند. (تلگرام دسکتاپ متن را لینک‌شده می‌چسباند؛ تلگرام گوشی فقط متن ساده می‌گیرد، پس آنجا متن و زیرش آدرس لینک می‌آید.)
3. **کپی کد مارک‌داون**: همان لینک به شکل `[متن](لینک)`.

اگر متن انتخابی بلند باشد (بیش از ۵۰ نویسه)، در گزینهٔ ۲ و ۳ متنِ لینک با «...» کوتاه می‌شود؛ کنار این دو گزینه کلید **«متن کامل»** نمایش داده می‌شود که با روشن‌کردنش متن کامل و بدون سه‌نقطه نوشته می‌شود. خودِ لینک همیشه به کل متن انتخاب‌شده می‌رسد.

لینک همان آدرس مقاله با `?find=متن` است (برای متن بلند `&e=` انتهای متن و برای تکرار چندباره `&n=شماره`). کد: `src/components/SelectionCopyMenu.tsx`، `src/lib/textLink.ts`، و `describeRange` / `locateText` در `src/lib/findInPage.ts`.

</details>

## ۲۷. دکمهٔ «بده هوش مصنوعی برام خلاصش کنه»

<details>
<summary>انتخاب یکی از شش هوش مصنوعی و باز کردن آن با پراپمت انگلیسی و آدرس دقیق صفحه؛ انتخاب ذخیره می‌شود و با × عوض می‌شود. متن کامل مقاله برای خواندن آن‌ها در prerender هم هست.</summary>

بالای هر مقاله (زیر مسیر صفحه) این دکمه هست:

1. **بار اول** پنجره‌ای می‌پرسد «کدوم هوش مصنوعی رو ترجیح میدی برات خلاصه کنه؟» با آیکن Arena AI، Claude، ChatGPT، Grok، Gemini و DeepSeek. با انتخاب یکی، همان لحظه خلاصه‌کردن شروع می‌شود.
2. **دفعه‌های بعد** کنار دکمه آیکن همان هوش مصنوعی هست و کلیک مستقیم آن را باز می‌کند. کنارش یک **×** هست که دوباره پنجره را می‌آورد؛ انتخاب از طریق ×، فقط ترجیح را عوض می‌کند و چیزی باز نمی‌شود. (انتخاب در مرورگر خواننده می‌ماند.)
3. هر بار یک **پراپمت انگلیسی** با **آدرس دقیق همان صفحه** آماده می‌شود: «کلمه‌به‌کلمه بخوان؛ مقدمه و همهٔ `##` و `###` را دقیق خلاصه کن؛ از خودت تفسیر نکن؛ معنای متن کامل را برسان؛ اگر نتوانستی لینک را باز کنی یا بخوانی چیزی از خودت ننویس، پیام فارسیِ «متأسفانه نتوانستم…» را بده و همین آدرس را بنویس تا خواننده برگردد و هوش مصنوعی دیگری را انتخاب کند.»
4. برای **مقاله‌های media** بندهای «چیزهایی که صددرصد باید در خلاصه باشد» هم به پراپمت اضافه می‌شود: مصدر هر نقل (با خلاصهٔ ترجمهٔ فارسی و همان متن عربیِ دقیق، در جایی که متن فارسی خلاصه شده)؛ اگر مصدر نبود و متن عربی بود، متن عربی کامل + خلاصهٔ ترجمه؛ اگر متن عربی نبود، متن فارسیِ آن نقل کوتاه نمی‌شود و کامل می‌آید. برای کتاب‌ها این بند نیست.

**پراپمت همیشه در کلیپ‌بورد هم کپی می‌شود** و اعلان می‌آید. ChatGPT و Grok و Claude پراپمت را از آدرس (`?q=`) می‌گیرند و در کادرشان می‌نشانند. Arena و Gemini و DeepSeek راهی برای پرکردن کادر از آدرس ندارند؛ آنجا فقط باز می‌شوند و خواننده باید پیست کند (Ctrl+V). اگر روزی یکی از این آدرس‌ها عوض شد، در `src/lib/summaryAi.ts` (`summaryAis`) درستش کنید. متن پراپمت هم همان‌جا در `buildSummaryPrompt` است. آیکن‌ها (`src/components/AiIcons.tsx`) نقاشی‌های ساده‌اند، نه لوگوی رسمی؛ برای لوگوی رسمی همان‌جا جایگزین کنید.

**نکتهٔ مهم:** سایت یک SPA است و هوش مصنوعی‌ها معمولاً جاوااسکریپت اجرا نمی‌کنند. برای همین `npm run build` حالا متن کامل هر مقاله (و هر صفحهٔ کتاب) را به‌صورت HTML ساده داخل صفحهٔ prerender هم می‌گذارد (`scripts/lib/static-body.ts`)، تا آدرس خود صفحه برای آن‌ها قابل‌خواندن باشد. این فقط پس از build و انتشار اثر دارد؛ در `npm run dev` ندارد.

</details>

## ۳۰. تصویر پیش‌فرض و لودینگ تصویر

<details>
<summary>مقاله‌بی‌تصویر منظره‌ای متحرک (روز/شب، ابر و کلاغ تصادفی و بسیار آهسته) نشان می‌دهد و تصویر در حال بارگذاری یک جعبهٔ درخشان با آیکن عکس.</summary>

- **مقاله‌بی‌تصویر (`NoImage`)**: دیگر فایل ثابت `noImage.svg` نیست؛ همان منظره به‌صورت SVG داخل صفحه کشیده می‌شود تا از تم سایت (روشن/تیره) رنگ بگیرد (متغیرهای `--no-image-*` در `src/styles/theme.css`). **روز:** نور خورشید کم‌وزیاد می‌شود، پرتوها آهسته می‌چرخند، درخت‌ها نرم تکان می‌خورند و برق‌های چمن چشمک می‌زنند. **شب (تم تیره):** ستاره‌ها چشمک می‌زنند و ماه می‌درخشد. **در هر دو:** ابر و کلاغ از یک طرف تصویر می‌آیند و از طرف دیگر می‌روند؛ آن‌قدر آهسته که در نگاه اول حرکتشان معلوم نیست (ابر ۱۵۰ تا ۲۴۰ ثانیه، کلاغ ۹۰ تا ۱۴۰ ثانیه برای یک عبور). هر بار **تصادفی** است: یک تا سه ابر، یک تا سه کلاغ (دسته‌ای پشت‌سرهم)، یا یک ابر با یک کلاغ؛ جهت هم تصادفی است. وقتی همه‌شان رد شدند، چند ثانیه مکث و بعد رویداد بعدی (و هر تصویر برای خودش شروع متفاوتی دارد). برای کندتر/تندتر کردن، `CLOUD_SECONDS` و `CROW_SECONDS` و برای تغییر احتمال هر رویداد `SKY_EVENTS` را در `src/lib/skyEvents.ts` عوض کنید. بقیه انیمیشن‌ها CSS است (`.no-image …` و `.ni-*` در `src/index.css`)؛ اگر «کاهش حرکت» در سیستم‌عامل روشن باشد هیچ‌چیز حرکت نمی‌کند و دو ابر ثابت می‌ماند. کد: `src/components/NoImage.tsx`.
- **در حال بارگذاری تصویر (`ImageWithFallback`)**: تا وقتی تصویری که آدرسش درست است هنوز از هاست نیامده، به‌جای کادر سفید یک جعبهٔ کم‌رنگ با آیکن تصویر و درخشش متحرک دیده می‌شود (کلاس `image-loading` در `src/index.css`)، تا معلوم باشد آنجا جای عکس است. با رسیدن تصویر برداشته می‌شود؛ اگر تصویر نیاید، منظرهٔ بالا نشان داده می‌شود.

</details>

## Add, update and delete content

<details>
<summary>Content tree and categories (<code>media</code>, <code>books</code>), the registry, the publish/delete commands, automatic push, and the «not finished yet» notice.</summary>

The current content tree has independent top-level categories: `content/media/` → `/media/` and `content/books/` → `/books/`. Discovery is recursive. Any directory with `index.md` is an article; a directory without it is a listing page. For example, `content/media/lives-nour/topic/index.md` maps to `/media/lives-nour/topic`. Keep article media beside its `index.md`; book page files go under that book's `pages/<number>.md`. The reserved `content/<category>/story/` directory is excluded from normal discovery.

The development watcher registers new article paths in `content/media.json` or `content/books.json`. Registry keys are paths relative to their category root; fields are `date`, `updated`, `completed`, `published`, `route`, and `name`. Missing names are filled from the folder in English; a manually entered Persian `name` is retained. See [CONTENT_PIPELINE.md](CONTENT_PIPELINE.md) for the author workflow and story commands.

| Command | What it does |
|---|---|
| `npm run publishMedia -- <folder>` (`publishBlog` alias) | Mark the article complete, rebuild content, then commit and push blog changes to `main`. |
| `npm run deleteMedia -- <folder>` (`deleteBlog` alias) | Delete the article folder and its dates, rebuild content, then commit and push the deletion. |
| `npm run createTestMedia` (`createTest` alias) | Restore the full `_example-media` test fixture, with no arguments. Existing fixtures are not overwritten. |
| `npm run deleteTestMedia` (`deleteTest` alias) | Delete the fixed `_example-media` fixture. |

`createNewBlog` and `updateBlog` are no longer separate commands. Create a folder under `content/media/<path>/` or `content/books/<path>/`, add `index.md`, and run `npm run dev` to register it. `publishMedia` (`publishBlog` alias) / `publishBook` accept nested relative paths. After publishing marks an article complete, saving changes to its Markdown or media files automatically updates `updated`, rebuilds the content and pushes that category's files to GitHub. Incomplete articles are not auto-pushed.

Automatic push requires the local clone to be on branch `main`, an `origin` remote pointing to `https://github.com/mohammadmahdiyan/weblogs`, and working GitHub authentication. The existing `.github/workflows/deploy.yml` builds and deploys the site after a push to `main`; the public site may take a few minutes to refresh.

```bash
npm run publishMedia -- my-post
npm run deleteMedia -- my-post
npm run createTestMedia
npm run deleteTestMedia
```

Until `publishMedia` (`publishBlog` alias) / `publishBook` is run for an article (new or old), its end shows a «not finished yet» line with a Telegram link. The publish command writes `"published": true` and marks it complete in the appropriate category registry; use paths relative to that category root. Test folders begin with `_` and are excluded from production output, sitemap and RSS.

</details>

## Search suggestions

<details>
<summary>Exact <code>suggestions</code> / title matches go straight to the article; <code>محتوا::term</code> searches inside article text and opens the page at the found text.</summary>

If a visitor submits a phrase that exactly equals (after normalization) a `suggestions` entry or a title, they are taken straight to that article. Fuzzy matches only show the result list. Typing `محتوا::term` searches inside article text; each result shows the article title, then a description with the found text exactly in the middle (equal context on both sides). Clicking a result opens the article at `?find=term`, which scrolls to the first occurrence, highlights it and opens any accordion / `<details>` hiding it. When a normal search finds nothing, the dropdown offers «search in the content» (which rewrites the box to `محتوا::term`) above the usual «not found» line; if the content search also finds nothing, only «not found» is shown.

</details>

## Embeds (iframes)

<details>
<summary><code>::youtube</code>, <code>::instagram</code>, <code>::aparat</code>, <code>::embed</code>, raw iframes and <code>:::source</code>, all through <code>SafeEmbed</code> with an allowlist and a failure fallback.</summary>

All frames use `SafeEmbed`: sandbox, referrer policy, lazy loading, click-to-load for video providers, an allowlist notice, an 8-second failure timeout with a link-card fallback, and an expand-to-modal button. Add your hadith site's hostname to `embedAllowlist` in `src/site.config.ts`. `public/_headers` is generated with a matching CSP `frame-src`.

## Look, themes, fonts

<details>
<summary>One article layout with small reader choices (palette, accordion, quote, button), light/dark/system themes, fonts, inline extras and the automatic Basmala.</summary>

There is one article layout. Readers can only make small changes from the «ظاهر» menu: colour palette (7), accordion look (3), quote look (3) and button look (3). The choice is saved in the browser and set as `data-palette / data-accordion / data-quote / data-button` on `<html>`; see `src/lib/appearance.ts`, the end of `src/styles/theme.css` and `src/styles/blog-styles.css`. Themes are light / dark / system (default system); the default font is Vazir and more fonts can be added in 3 steps (`public/fonts/README.md`). Users can change font and size from the home page.

Inline extras in Markdown text: small text `((text))(سایز: کوچک|متوسط|بزرگ،قرارگیری: بالا|وسط|پایین)` (defaults: medium, top) and emoji (typed as the emoji itself, or `{😂}`), registered in `src/emojis/emojis.ts` next to their `.svg` files.

Every article starts with the Basmala and the salawat (centred, each with a smaller Persian translation below); it is added automatically by `src/components/Basmala.tsx`, so do not write it in the md files.

</details>

## Gallery

<details>
<summary><code>:::gallery</code> takes any mix of photos, GIFs and videos; the layout depends on the count and the reader's font size; click opens a lightbox.</summary>

`:::gallery` takes any mix of photos, GIFs and videos (`![](a.jpg)`, `![](b.gif)`, `![](c.mp4)`, `::video{link="…"}`), one per line; click opens a lightbox that steps through the whole set. Layout by count at 100% font size: 1 = plain media (no gallery), 2 = side by side, 3 = 2 + 1 full width, 4 = 2 × 2, 5 = 3 + 2, 6 = 3 + 3, more continue with rows of up to 3 (7 = 3+2+2, 8 = 3+3+2, …). Items per row follow the reader's font size: larger text → fewer per row (6 items at 150% = 2+2+2), smaller → more (8 items at 80% = 4+4); narrow screens also reduce it so tiles never get tiny. Logic: `src/lib/gallery.ts`.

</details>

## Troubleshooting

<details>
<summary>Missing image, unstyled tag, empty iframe, invalid folder name and «no title found».</summary>

Image missing → keep it beside `index.md` and use `./file`. New tag unstyled → register it in `directiveNames` and the component map. Empty iframe → the source blocks framing, use `:::source`. Invalid folder name / slug conflict → rename the folder (it is the URL). "no title found" → add a `# Title` line.

</details>
